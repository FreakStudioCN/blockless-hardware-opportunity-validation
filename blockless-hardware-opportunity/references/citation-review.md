# 引用核对（强制）

自动校验只能查文件齐不齐、PDF 能不能渲染；它查不出"这句话记录里没有"。实测拿 300 字摘录写正文，一组四份文件里会出现 4 处错引、41 处超出记录的转述。所以写完之后必须有一个**没参与写作的核对者**逐条对照，才允许剥掉编号交付。

## 写作时

- 只从 `evidence/relevance-review.json` 的 `accepted_records` 取事实，读每条的完整 `body`，不读 `summary` 写作。
- 每一句"我们看见"都在句末标 `[n]`，n 是该记录在 `accepted_records` 里的序号（从 1 数）。一句话可以标多条。
- 直接引语（引号里的话）必须是记录原文的忠实翻译；记录里没有的话不能加引号写成"他说"。评论者性别未知时写"发帖人说"。
- 记录里没有的人名、地名、年份、金额、数量、机构名，一个都不能出现。项目名或工具名必须与记录 URL 或标题一致，说不准就写"一个开源项目"。
- 一个人的说法只能写成一个人的说法，不能写成"反复出现""共识""很多人"；要说"多条记录"就逐条标出来。
- `research-plan.json` 里我们自己列的替代品、假设、接口形态，不能写成"社区里有人说"；要写就标明"我们自己列的对照项，采集里没见到"。
- 采集数量按 `collection-log.json`（原始条数）和 `evidence/clusters/summary.json`（去重条数）如实分开写，不混用。
- 没有记录支撑的价格一律写"价格未核实"；有记录的价格写清是哪条记录说的。
- 四份文件先写成带 `[n]` 的内部版，保存到 `evidence/internal-with-citations/`，文件名与发送版完全相同。

## 核对者的任务

派一个没有看过写作过程的子代理或另一个模型，只给它：内部版四份文件、`relevance-review.json`、`research-plan.json`、`collection-log.json`、`clusters/summary.json`。它逐条阅读每个 `[n]` 并判定：

- **OK**：转述忠实，引语是原文的忠实翻译，没有记录里没有的人名/年份/金额/数量/机构名。
- **STRETCH**：方向对，但加了记录里没有的细节、引语、数字；或把一个人的话说成多数人；或把标题的字面意思和正文的因果说反。
- **WRONG**：引用的记录和句子说的事无关，或编号引错。

另外扫描所有没有 `[n]` 的具体数字（价格、金额、年份、人数、百分比、采集条数）和带引号的引语，判断有没有出处（记录、创作者原始提交、collection-log、summary.json）。方法参数（10 分钟、3–5 人、评分区间）不算。

结果写入 `evidence/citation-review.md`，每轮追加一节，格式固定：

```
## 第 N 轮 <日期>
复核结果：引用 87 处，OK 84，STRETCH 3，WRONG 0
- 报告 · 现成的替代品 · [24] · "SNOO 1700 美元" → [24] 讲的是创业者的家庭时间，价格在 [26] → 改成 "……1700 美元 [26]"
- 人味版 · 第 3 段 · 无编号 · "2019 年" → 没有记录给年份 → 删掉年份
```

核对者不改文件。写作者只按清单逐条修改，其余原样保留，改完再核一轮。**直到最新一轮 STRETCH 0、WRONG 0，且内部版此后没有再改动**，才运行：

```powershell
python .\blockless-hardware-opportunity\scripts\strip_citations.py --case-dir .\output\<slug>
```

它把内部版剥掉 `[n]` 写成发送版，并拒绝任何研究黑话（词法、误命中、token、429、相关性审核、候选记录、聚类、TF-IDF、KMeans、种子页、门禁、评估结果、审判、暂不推进、Kill、楔子、证伪、skill、簇）。发送版对创作者说"我们用关键词自动筛选，筛出来的只是谈到了这个话题的帖子，不代表有人要买"，不说方法名。

`validate_client_delivery.py` 会检查：内部版存在且每份都有 `[n]`；每个 `[n]` 都能在 `accepted_records` 里找到；发送版与内部版剥编号后逐字相同；`citation-review.md` 最新一轮 STRETCH 0 / WRONG 0 且晚于内部版的最后修改。任何一项不满足都不得交付。
